A workspace for material you keep coming back to.

Put a document, recording, video or web page in. Get a summary, keep the original, and be able to find and re-read it months later. What you've saved can then be read across — traced back to its source, laid out in order, or checked for figures that disagree.

What it is, plainly

The summarising is done by a language model, and a chat assistant will summarise a document perfectly well too. That part is not the reason this exists, and it would be dishonest to present it as one.

What it does that a chat window does not: it keeps your material. The original file is stored and playable, not discarded once the text has been extracted. A recording made eight months ago can still be listened to. Everything saved stays searchable, and the analysis tools run over the whole collection at once rather than over whatever you last pasted in.

Several of those tools need no AI service at all — they are algorithms running on your own stored text, which makes them fast, free, repeatable, and functional when an API key is missing or an upstream service is down.

The parts worth pointing at

Tracing a summary to its source

Every sentence of a summary is matched to the passage of the original it came from, by local sequence alignment, and the result is a character position you can jump to. Sentences nothing supports are flagged. A model asked to cite itself will often invent the citation; this computes it.

Figures that disagree

Quantities are extracted across everything you've saved and normalised through a unit conversion graph, so two sources stating a different number for the same thing are surfaced. Currencies are never converted, because exchange rates are prices rather than definitions.

Chronology

Dates are parsed out of your sources by grammar, including relative ones, and resolved against the document that wrote them rather than against today. The result is an ordered account of what your material describes.

Built rather than assembled

The analysis in this application is implemented directly rather than delegated. Porter stemming, Smith-Waterman alignment with affine gaps, a date grammar, an affine unit-conversion graph, the constellation algorithm for acoustic fingerprinting, conflict-free replicated data types, a recursive-descent parser for a small rule language, and a SHA-256 hash chain with Merkle membership proofs — roughly ten thousand lines in app/core/, depending on nothing beyond the standard library and NumPy, each module carrying a test suite you can run on its own.

Calls to the language model go through a retry chain, a circuit breaker and a rate limiter, and fall back to local extractive summarisation when every model is unavailable, so a busy API day degrades the output rather than breaking the page.

If all you need is a one-off summary, use a chat assistant — it will be quicker and it is free. This is for material you intend to keep.
